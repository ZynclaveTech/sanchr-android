# iOS interop test fixtures

Golden bytes produced by the iOS XCTest interop suite that the Android
`AndroidIosInteropTest` consumes to prove decryption compatibility without
needing a running iOS peer. Regenerated whenever either platform changes
any of:

- `libsignal-client` version (Android AAR / iOS SPM must agree).
- Sealed-sender certificate format.
- Envelope proto wire shape (any field in `sanchr.messaging.SealedEnvelope`
  or the inner `UnidentifiedSenderMessageContent`).

## Files

Each fixture is the raw bytes the Android client would observe on the wire
after a successful server-side fan-out. No framing, no length prefix.

| File | What it is | Regenerated by |
|---|---|---|
| `sealed-envelope-v1.bin` | A single iOS-to-Android sealed-sender text message, encrypted to a well-known Android test identity. | `SealedSenderInteropXCTest.testExportAndroidGolden` (iOS repo) |

## Regeneration workflow

Run from the **iOS** repo (`ZynclaveTech/sanchr-ios`):

```bash
xcodebuild test \
  -scheme SanchrApp \
  -destination 'platform=iOS Simulator,name=iPhone 15' \
  -only-testing:SanchrAppTests/SealedSenderInteropXCTest/testExportAndroidGolden
```

The test writes new golden bytes to
`Tests/fixtures/sealed-envelope-v1.bin` in the iOS repo. Copy them across:

```bash
cp \
  /path/to/sanchr-ios/Tests/fixtures/sealed-envelope-v1.bin \
  /path/to/sanchr-android/app/src/androidTest/assets/ios-fixtures/sealed-envelope-v1.bin
```

Commit both repos in the same PR pair (cross-reference commit SHAs in the
PR body) so reviewers can verify the export side matches the import side.

## Why this fixture lives committed, not regenerated in-CI

Running the iOS XCTest suite on CI would require a macOS runner just for
fixture regeneration — expensive and slow for a value that changes only
on the few commits that touch sealed-sender internals. Committing the
fixture makes the golden value a reviewable artifact and lets the
nightly-interop Android CI run on cheap Linux runners.

## Absence handling

When this directory contains no `sealed-envelope-v1.bin`, the
`AndroidIosInteropTest` skips via `Assume.assumeTrue` with a pointer back
to this README. That lets the interop test code land in `main` before the
first fixture handoff without turning the nightly CI red.
